# CONTRACT.md — cycling instance

## Instance identity
- **Domain:** competitive cycling — pacing plan from intent + sensor state
- **Data source:** synthetic (DECLARED) — threshold-based planner
- **Status:** verified

## Capability declarations

| Capability | Value | Evidence |
|---|---|---|
| HAS_GRADIENT_MODULATION | True | steep gradient reduces ATTACK ceiling; tested |
| HAS_FATIGUE_MODULATION | True | high fatigue reduces ATTACK ceiling; tested |
| HAS_RAMP_DECAY | True | ATTACK ramps up; RECOVER decays down linearly |
| OBSERVE_ONLY | Always True | plan is a suggestion — actuation is the consumer's decision |
| DATA_LABEL | DECLARED | threshold-based; no real power meter data |

## Confidence vocabulary

| Label | Meaning |
|---|---|
| OBSERVED | Raw input (power_w, gradient_pct, fatigue) |
| PLANNED | Target power sequence generated by the planner |

## Latency contract (Guardrail 8)
- Single plan(steps=N): O(N), < 1ms for N ≤ 600
- **Exposed variable:** `plan.dt_ahead` — seconds the plan covers
- Consumer must compare `dt_ahead` against their event horizon before acting

## Key verified findings (DECLARED thresholds, ftp=300W)
- ATTACK plan holds > 105% FTP after ramp (moderate gradient, low fatigue)
- Steep gradient (14% vs 2%) measurably reduces ATTACK ceiling
- High fatigue (0.80 vs 0.10) measurably reduces ATTACK ceiling
- RECOVER plan reaches ≤ 55% FTP after decay phase
- MAINTAIN plan stays within [0.56, 1.04] FTP band regardless of gradient

## What this instance does NOT do
- Does not model team tactics (domestique work, drafting)
- Does not adapt the plan mid-execution — each call is stateless
- Does not learn from past rides — all targets are DECLARED
- Does not govern whether the athlete should receive the plan (that is `sensory_architecture_factory`)
